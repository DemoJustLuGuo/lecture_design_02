# 题目5项目规划

## 1. 项目定位

课程设计题目为：

```text
基于AI的智能通信故障检测与诊断系统
```

本项目面向通信网络运行维护场景，围绕信号中断、误码率过高、带宽不足、基站故障、信道干扰等典型问题，完成从通信网络数据采集或模拟，到异常检测、故障分类、故障定位、诊断建议、日志统计与可视化的完整闭环。

项目主线固定为：

```text
通信网络数据模拟 -> 异常检测 -> 故障分类 -> 故障定位 -> 诊断建议 -> 日志统计与可视化
```

开发时应优先保证主流程可运行、指标可复现、演示可完成，再考虑复杂模型和界面增强。

## 2. 指导书要求摘要

题目5的核心要求包括：

1. 结合通信网络故障类型，利用AI技术实现故障的实时检测、类型识别、定位及诊断建议。
2. 完成软件系统开发，实现数据采集、故障检测、故障识别、定位、诊断全流程。
3. 故障检测准确率目标不低于95%。
4. 无线场景下定位误差目标不超过50米。
5. 具备多终端交互能力，至少应覆盖PC端管理界面和移动端预警提示的展示能力。
6. 支持故障日志查询与统计分析。
7. 需要提交源代码、可运行程序或运行说明、课程设计报告、测试数据、答辩PPT和演示视频。

通用要求包括：

1. 软件程序必须可运行，具备完整功能模块。
2. 报告不少于3000字，包含需求分析、总体设计、详细设计、测试结果、性能分析、总结与展望。
3. 必须说明AI技术与通信专业知识的结合，不能只简单调用算法库。
4. 需要保留测试数据、图表、截图和大模型辅助设计提示词记录。

## 3. 总体目标

项目验收时应重点证明以下能力：

1. 覆盖至少4类典型通信故障。
2. 能说明每类故障与通信指标之间的关系。
3. 能展示AI方法在异常检测或故障分类中的作用。
4. 能用准确率、召回率、F1、混淆矩阵、定位误差和检测耗时等指标证明系统效果。
5. 能给出面向运维人员的故障诊断建议。
6. 能通过Web界面展示网络状态、故障日志、故障位置和统计结果。

## 4. 功能模块规划

本节给出功能模块的简要规划。面向课程设计报告和论文写作时，建议优先采用“功能模块视角”描述系统结构，而不是直接按前端、后端、数据库等技术层描述。详细结构说明见：

```text
docs/system_function_structure.md
```

### 4.1 数据采集与模拟模块

该模块负责生成或接入通信网络运行数据。课程设计阶段优先采用可控的数据模拟方案，并保留固定随机种子，保证结果可复现。

建议模拟字段包括：

| 字段 | 含义 |
| --- | --- |
| `timestamp` | 采样时间 |
| `station_id` | 基站编号 |
| `station_name` | 基站名称 |
| `longitude` | 经度 |
| `latitude` | 纬度 |
| `rsrp` | 参考信号接收功率 |
| `sinr` | 信干噪比 |
| `ber` | 误码率 |
| `bandwidth_usage` | 带宽占用率 |
| `latency_ms` | 网络时延 |
| `packet_loss` | 丢包率 |
| `device_status` | 设备状态 |
| `fault_type` | 故障类型标签 |
| `is_fault` | 是否故障 |

建议先生成不少于3000条数据，并注入至少4类故障样本。

### 4.2 故障检测模块

该模块判断当前网络状态是否异常。

推荐实现：

```text
IsolationForest
```

选择理由：

1. 适合结构化通信指标异常检测。
2. 训练速度快，方便课程设计演示和复现实验。
3. 比复杂深度学习模型更容易解释。

可扩展方案：

```text
AutoEncoder
```

在主流程稳定后，可将AutoEncoder作为增强模型或对比模型。

### 4.3 故障分类模块

该模块对异常样本进一步识别故障类型。

推荐实现：

```text
RandomForestClassifier
```

可选增强：

```text
XGBoost
SVM
MLP
```

推荐故障类型：

| 故障类型 | 典型指标表现 |
| --- | --- |
| 信号中断 | RSRP显著下降，SINR下降，丢包率升高 |
| 误码率过高 | BER明显升高，SINR降低，链路质量变差 |
| 带宽不足 | 带宽占用率过高，时延升高，吞吐能力下降 |
| 基站故障 | 设备状态异常，多项指标同时恶化 |
| 信道干扰 | SINR下降，BER升高，丢包率升高 |

### 4.4 故障定位模块

该模块根据异常基站位置、终端测量信息或信号强度估算故障位置。

课程设计阶段推荐使用：

```text
加权质心定位
```

定位输出应包括：

1. 预测经纬度。
2. 真实或模拟故障经纬度。
3. 定位误差，单位为米。
4. 是否满足50米误差目标。

如后续数据条件允许，可扩展为三角定位或基于路径损耗模型的定位方法。

### 4.5 诊断建议模块

该模块根据故障类型、故障位置和严重程度输出运维建议。

建议采用规则引擎实现，保证稳定、可解释、易演示。

示例规则：

| 故障类型 | 诊断建议 |
| --- | --- |
| 信号中断 | 检查基站供电、传输链路、射频模块和天馈系统 |
| 误码率过高 | 检查信道干扰、编码配置、设备老化和链路质量 |
| 带宽不足 | 检查流量拥塞，调整资源分配，优化负载均衡 |
| 基站故障 | 查看设备告警，重启相关服务，切换备用设备 |
| 信道干扰 | 排查干扰源，调整频点，优化发射功率 |

### 4.6 日志统计与可视化模块

该模块负责保存检测结果，并为前端页面和报告图表提供数据。

应支持：

1. 故障日志查询。
2. 故障详情查看。
3. 按故障类型统计数量和占比。
4. 按时间统计故障趋势。
5. 展示检测准确率、分类准确率、召回率、F1。
6. 展示混淆矩阵。
7. 展示定位误差分布。
8. 展示检测耗时。

### 4.7 前端展示模块

前端应采用管理系统风格，首屏进入监控总览，不做营销式首页。

建议页面包括：

| 页面 | 作用 |
| --- | --- |
| 监控总览 | 展示网络状态、故障数量、关键指标和实时告警 |
| 基站管理 | 展示基站列表、状态和运行指标 |
| 基站详情 | 查看单个基站指标曲线和故障记录 |
| 故障日志 | 查询历史故障和检测结果 |
| 故障地图 | 展示基站位置、故障位置和定位结果 |
| 诊断建议 | 展示故障原因分析和处理建议 |
| 模型评估 | 展示准确率、召回率、F1、混淆矩阵和定位误差 |
| 移动预警 | 模拟移动端预警提示 |

## 5. 技术路线

建议技术栈：

| 层级 | 技术 |
| --- | --- |
| 后端 | Python, FastAPI, Uvicorn |
| 数据处理 | NumPy, Pandas |
| AI模型 | Scikit-learn, XGBoost |
| 数据库 | SQLite |
| 模型持久化 | Joblib |
| 测试 | Pytest |
| 前端 | React, Vite, Tailwind CSS |
| 状态管理 | React state/hooks |
| 请求库 | Axios |
| 图表 | ECharts |
| 地图 | Leaflet |

优先技术路线：

```text
数据模拟 + IsolationForest异常检测 + RandomForest故障分类 + 加权质心定位 + 规则诊断 + React可视化
```

该路线实现成本可控，便于演示和写报告，也能覆盖指导书中的主要要求。

## 8. 答辩演示故事线

建议演示顺序：

```text
展示正常网络状态
-> 触发或加载故障数据
-> 系统检测到异常
-> 显示故障类型
-> 显示故障位置
-> 给出诊断建议
-> 查看历史日志和统计图
-> 展示测试准确率、混淆矩阵和定位误差
```

当前可增加一条增强演示路线：

```text
进入设置页查看演示流程状态
-> 生成、导入或重载演示数据
-> 配置大模型 API
-> 打开诊断建议页
-> 点击 AI 增强诊断
-> 对比规则诊断和大模型增强诊断来源
-> 采纳建议并更新故障状态
-> 导出 Markdown 诊断报告
```

该故事线能够同时证明：

1. 系统可运行。
2. AI模型参与了检测和分类。
3. 通信指标和故障类型之间有关联。
4. 系统能给出实际运维建议。
5. 测试结果可量化。

## 10. 风险和优先级

主要风险：

1. 过早投入复杂深度学习模型，导致主流程无法按时闭环。
2. 只完成界面，没有可复现测试指标。
3. 故障类型与通信指标关系解释不清。
4. 日志、统计和诊断建议缺失，导致系统不像完整运维系统。
5. 报告和答辩材料准备过晚。

优先级：

1. 先完成数据模拟、故障注入、模型训练和评估。
2. 再完成后端API和数据库闭环。
3. 再完成前端总览、故障日志、模型评估和地图展示。
4. 再整理截图、测试图表、报告和PPT。
5. 最后考虑AutoEncoder、LSTM、移动端增强和界面细节优化。
